# Plasticity Workbench: запуск и восстановление

## Установка и запуск

Требования: macOS Apple Silicon, Plasticity 26.1.3 и Node.js 24.

```sh
npm install
npm run setup:codex
npm run start:plasticity
npm run start:workbench -- --lan
```

Если Plasticity уже запущена без MCP-доступа, launcher оставит её и все
открытые документы нетронутыми. Сначала сохраните работу, закройте приложение,
затем снова выполните `npm run start:plasticity`.

Последняя команда собирает веб-интерфейс, выбирает первый активный частный IPv4-адрес и печатает адрес вида `http://192.168.1.20:4317`. Без `--lan` сервер слушает только `127.0.0.1`. На Mac откройте владельческую сессию отдельной командой `npm --workspace workbench run open:owner -- --lan`; при запуске сервера без `--lan` опустите этот флаг и здесь. Команда открывает браузер с секретом во фрагменте URL; интерфейс обменивает его на HttpOnly cookie и сразу удаляет фрагмент из адресной строки. Не пересылайте владельческую ссылку. Обычный адрес сервера не даёт доступа к проектам.

`setup:codex` подключает Git marketplace этого репозитория и устанавливает плагин с обоими MCP. После установки откройте новый чат Codex. Если используете Codex без плагина, зарегистрируйте MCP напрямую:

```sh
codex mcp add plasticity -- npm --prefix "$PWD" start
codex mcp add plasticity-workbench -- npm --prefix "$PWD/workbench" run mcp
```

Второй MCP сам ищет сервис на loopback и локальных приватных IPv4. Если сервис не запущен, MCP поднимает его с `--lan` и останавливает созданный им процесс при завершении. `WORKBENCH_ORIGIN` нужен только для явного переопределения адреса. MCP читает локальный `owner-token` из каталога проектов Workbench; файл создаётся с правами только владельца и должен оставаться на этом Mac. Если задан `WORKBENCH_PROJECTS_ROOT`, используйте одинаковое значение для HTTP-сервиса, MCP и команды открытия браузера.

## Работа с проектом

Проект хранит монотонную ревизию, версии STEP, точные измерения B-Rep, таблицы, аннотации, референсы, контрольные снимки журнала построения и задания печати. Агент выбирает проект через `workbench_list_projects` или создаёт через `workbench_create_project`, затем читает `workbench_project_status` перед каждой публикацией и передаёт текущую `expectedRevision`. Конфликт ревизии не перезаписывает данные. После значимого этапа агент читает `plasticity_construction_journal` и сохраняет результат через `workbench_publish_construction_journal`; эти снимки переживают перезапуск обоих MCP-процессов.

В браузере владелец может создать проект кнопкой **Новый проект**. На узком экране проекты доступны в горизонтальной панели над моделью. Если открыть обычный адрес без владельческой сессии, Workbench покажет команду для входа на Mac; ссылка планшета даёт доступ только к своему проекту.

Общение с агентом ведётся только в Codex. Workbench принимает структурированные действия: числовые поля размеров, пакет аннотаций и отдельное подтверждение печати. HTTP approve/submit доступны только владельческой сессии или MCP с токеном владельца; даже планшетная сессия с правом `edit` не запускает принтер. Ограничения `min`, `max`, `step` и целочисленный тип проверяются и в браузере, и повторно на сервере. Агент читает принятые изменения через `workbench_get_feedback` или `workbench_wait_for_feedback`.

Панель модели содержит рабочие команды ракурса, ортографические виды спереди и сверху, Z-сечение, вписывание, выбор, скрытие, изоляцию и прозрачность отдельных тел. Кнопка строки таблицы с `linkedEntities` выбирает соответствующее тело или грань; выбор в модели подсвечивает связанные строки. При рисовании поверх тела Workbench сохраняет мировую точку и доступный ID B-Rep тела/грани, а не только экранные координаты. Диалог «Поделиться» на Mac показывает активные одноразовые ссылки и планшетные сессии; кнопка «Отозвать» немедленно закрывает доступ выбранной сессии без работы с базой данных вручную.

Кнопка **Поделиться** создаёт одноразовую ссылку с правом `annotate` на 24 часа. Откройте её на планшете в той же Wi‑Fi сети. Код удаляется из адресной строки после обмена на HttpOnly cookie. Перо, маркер, стрелка, точка, текстовая заметка и размер остаются видимыми поверх выбранной версии модели и сохраняются локальным черновиком IndexedDB, пока пользователь не нажмёт **Передать изменения агенту**. Размерная аннотация принимается только как число с единицей; ошибочный последний элемент можно удалить до отправки. При переключении версии Workbench загружает отдельный черновик и показывает только относящиеся к ней отправленные аннотации.

Просмотрщик тесселирует STEP в отдельном Web Worker. Все размеры курсором и границы сетки считаются приближёнными. Таблицы с источником `native-brep` содержат контрольные значения Plasticity. При ошибке нового STEP предыдущая версия остаётся видимой.

Перед публикацией версии агент экспортирует STEP в `workspacePath` проекта и вызывает `workbench_upload_project_artifact` с относительным путём. Инструмент принимает только обычные файлы внутри этого каталога, проверяет выход через `..` и симлинки, определяет тип по разрешённому расширению и передаёт серверу байты. HTTP API по-прежнему не принимает путь к локальному файлу.

Референс регистрируется только после проверки агентом. `workbench_register_reference` принимает URL и/или уже загруженный в проект артефакт, лицензию, класс источника, роль `locked-reference` либо `functional-envelope` и таблицу размеров. Размер без надёжного значения получает `measurement-required`; критичные строки остаются видимыми до ввода пользователем. Workbench не является загрузчиком из интернета и не выполняет URL из записи.

## Подготовка и запуск печати

На этом Mac проверен официальный Creality Print 7.2.2.5483 arm64 с профилями `Creality K1C 0.4 nozzle` и `0.20mm Standard`. Workbench перечисляет совместимые с выбранной машиной filament-профили отдельно; живая проверка каталога подтвердила Creality `CR-PLA` и `Hyper PLA` наряду с Generic PLA. Выбор профиля описывает настройки слайсера и не квалифицирует механические свойства катушки. Установленный Intel-only `/Applications/Creality Print.app` сохранён без изменений; Workbench на Apple Silicon автоматически предпочитает `/Applications/Creality Print (Apple Silicon).app`. Для другого пути задайте `CREALITY_PRINT_EXECUTABLE` и `CREALITY_PRINT_RESOURCES_ROOT` (папку `Contents/Resources`) в окружении Workbench. Creality Print 7.2 CLI не импортирует STEP: агент хранит STEP как редактируемый источник и экспортирует из Plasticity отдельный бинарный STL в миллиметрах через `plasticity_export_stl`. Живой маршрут Plasticity 26.1.3 → STL → CLI дал 25 слоёв и реальные габариты траекторий 20 × 10 × 5 мм. 3MF того же тестового Solid CLI импортирует и измеряет, но завершает нарезку ошибкой, поэтому его нельзя считать поддержанным входом Creality Print. Слайсер принимает только проверенные для адаптера STL, OBJ или AMF. Производная сетка, профили и отдельный CLI `--datadir` копируются в каталог конкретного задания; общие настройки слайсера не меняются. В результате сохраняются SHA-256 STL и G-code, габариты траекторий, число слоёв, масса пластика и расчётное время.

Если в G-code нет собственных габаритов слайсера или object metadata, Workbench оценивает границы по ходам экструзии. Для дуг в плоскости XY учитываются крайние точки G2/G3 с I/J или signed R; для неизвестной или неподдержанной дуговой команды оценка отклоняется целиком, чтобы не пропустить выход за стол. Это оценка траектории, а не проверка того, что выбранная прошивка принтера умеет исполнять данный диалект G-code.

Полный путь дополнительно проверяется через изолированный HTTP-сервис и настоящий stdio Workbench MCP: MCP создаёт проект, прикрепляет STL, выбирает найденный профиль, запускает `workbench_assess_printability` и вызывает `workbench_slice_model`. В режиме `--plasticity-target` acceptance подключается к явно выбранному пустому документу Plasticity, создаёт тестовый Solid, применяет ровно ориентацию Workbench DFM (или подтверждает, что модель уже выровнена), сверяет B-Rep со STL и нарезает экспорт. Флаг `--split-native` требует явный `--split-joint flat|alignment-pins|tongue-and-groove|dovetail`; он берёт заведомо большую модель, задаёт 5 мм отступа от края стола, вызывает нативное разбиение по рекомендованному usable volume и при выборе alignment-pins, tongue-and-groove или dovetail формирует соответствующее нативное сопряжение на каждой найденной смежной паре тел через публичный Plasticity MCP-рецепт. После этого acceptance проверяет точные тела, объёмное пересечение соседей, отдельные STL и пакетную нарезку через один `workbench_slice_parts`. Размеры joint и зазор 0,2 мм в этой фиксированной тестовой сцене служат только для проверки механизма и не являются производственной рекомендацией или результатом испытания прочности. Каждый G-code preview читается из project asset endpoint и проверяется по границам; попытки `workbench_submit_approved_print` без подтверждения отклоняются, задания остаются `ready`, адаптер принтера не вызывается. Plasticity acceptance восстанавливает исходную пустую сцену, а cleanup отменяет изменения только при неизменившихся документе и revision. Обычная ориентация K1C дала ready-job на 25 слоях после поворота `[0,0,21.9]`; native split с двумя test-fixture шип-пазами дал три отдельных тела и три ready-job. Команда ориентации: `npm run accept:workbench-creality-mcp -- --plasticity-target EXPLICIT_WINDOW_ID --output NEW_DIRECTORY --executable /path/to/CrealityPrint --resources-root /path/to/Contents/Resources`; добавьте `--split-native --split-joint dovetail` для полного испытания соединённых частей. Для готового STL используйте `--input PLASTICITY_EXPORT.stl` вместо Plasticity target. Добавьте `--batch-parts 2` для живой проверки двух одинаковых batch items. Evidence: `/tmp/plasticity-mcp-output`; native split joints: `/tmp/plasticity-mcp-output`, `/tmp/plasticity-mcp-output`, `/tmp/plasticity-mcp-output`; batch: `/tmp/plasticity-mcp-output`.

Для разрезанной модели экспортируйте каждую отдельную часть из Plasticity в свой STL, прикрепите все STL через `workbench_upload_project_artifact`, затем вызовите `workbench_slice_parts` с уникальной меткой каждой части, её SHA-256, контрольными габаритами и одним выбранным профилем. Сервис сначала проверяет весь пакет (2–32 частей), ревизию, профили, прикрепление файлов и DFM; лишь затем создаёт самостоятельные задания слайсера для каждой части. Сбой одной нарезки отображается отдельно и не скрывает результаты остальных. Для каждой готовой части остаются отдельные G-code и подтверждение в Workbench. Пакетная нарезка не подтверждает и не запускает печать.

Экран **Подготовка к печати** показывает DFM-проверки и траекторию выбранного слоя. Кнопка подтверждения перечисляет точный хеш, принтер, материал и профиль. Разрешение также связывается с точным набором предупреждений и оценок времени и материала. Оно только разрешает агенту вызвать `workbench_submit_approved_print`. Если модель, проект, профиль, предупреждения или оценки изменились, разрешение недействительно. При тайм-ауте отправка переходит в `unknown`; агент вызывает `workbench_reconcile_print_submission`, который только читает `print_stats` и список G-code на принтере. Точный файл в текущем задании означает `submitted`. Файл только в хранилище оставляет состояние `unknown`, чтобы не запустить его повторно. Лишь подтверждённое отсутствие файла возвращает состояние `approved`; повторная отправка остаётся отдельным вызовом.

`workbench_printer_status` выполняет только чтение. Для обнаруженного K1C используется локальный Moonraker на порту 7125. Состояние берётся из `print_stats`, поэтому Klippy `ready` не маскирует уже идущую печать. Отправка допускается только в `standby`, `complete` или `cancelled`. Ни проверка статуса, ни нарезка не загружают файл на принтер.

Штатная прошивка K1C отклоняет обычную загрузку через свой форк `/server/files/upload`. Поэтому K1-адаптер повторяет контракт установленного Creality Print: один бинарный multipart-файл отправляется на `http://<printer>/upload/<ascii-name>`, после успешной записи точное имя запускается через Moonraker `/printer/print/start`. Имя ограничено коротким ASCII slug, ID задания и частью SHA-256; для полностью локализованного названия используется префикс `plasticity`. Живой тест подтвердил загрузку и запуск файла `80-40-8-e815d11e-9c113a5c8615.gcode` на K1C. Для обычных Moonraker-принтеров остаётся стандартный `/server/files/upload`.

Для смены принтера агент сначала вызывает `workbench_manufacturing_profiles` с фильтрами `slicer`, `printerVendor`, `printerModel`, `material` и/или `nozzleDiameterMm`. Выдача ограничена 20 профилями по умолчанию и поддерживает `offset`/`limit` (максимум 100 за страницу), поэтому большой каталог не раздувает контекст Codex. Для найденного профиля MCP передаёт `printer.id`, `material.id` и `slicer.id` в `workbench_register_manufacturing_profile`; Workbench разрешает их по единственному совпадению установленного каталога, копирует machine/process/filament JSON в `.manufacturing-profiles` и вычисляет SHA-256 каждого файла. Агенту не нужны и не выдаются локальные пути. Для пользовательского или импортированного пресета можно передать полный профиль через локальный MCP; Workbench сохраняет его как отдельную запись. Статус `draft`, `imported`, `official` или `user-verified` остаётся явным. MCP выдаёт безопасное описание зарегистрированного профиля и immutable `profileHash`; для оценки DFM, `workbench_slice_model` и `workbench_slice_parts` агент передаёт этот hash, а Workbench сам разрешает его к сохранённой конфигурации. Если профиль содержит эти настройки, каталог возвращает `nominalInfillPercent`, `sparseInfillPattern`, `wallLoops`, `topShellLayers` и `bottomShellLayers`; это исходные глобальные значения пресета, они могут отличаться от задания с per-object modifier. Вместе с `material.nozzleTemperatureC` и `slicer.layerHeightMm` оно помогает привязать купон к выбранному процессу, но не заменяет фактическую запись температуры/ориентации/настроек теста. Если слоевой график из G-code полон, `workbench_slicer_interface_heights` выдаёт только запрошенные номера интерфейсов, фактический deposition Z и готовый `relativeOffsetMm` от первого слоя вместе с хэшами job/profile/G-code. Агент передаёт эти offset в `plasticity_plan_cohesive_layer_planes` без ручного вычитания; весь график не попадает в контекст. Для проверки направлений дорожек на всех слоях, включая последний, `workbench_slicer_layer_path_orientations` возвращает выбранные индексы порциями до 32 вместе с фактическим deposition Z и теми же хэшами задания и G-code; неполное покрытие дуговых ходов остаётся явно отмеченным. Название производителя и модель сохраняются как указаны в источнике — контракт допускает сторонние принтеры, а наличие отдельного адаптера нарезки или отправки проверяется независимо. Профиль содержит материал и диаметр сопла, качество, поддержки, масштаб усадки, компенсацию отверстий, проверенный сборочный зазор, назначение детали и ожидаемую нагрузку. Нарезка принимает только профиль, который полностью совпадает с обнаруженной или зарегистрированной копией. На этом Mac живые Workbench MCP проверки прошли для Creality K1C через Creality Print и OrcaSlicer; результаты оставались `ready` до отдельного подтверждения.

Если модель не помещается, `workbench_assess_printability` проверяет осевые и диагональные ориентации. Его `rotationDeg` и `sizeMm` относятся к проверенной ревизии модели. Для одного Solid или жёсткой группы Solid агент передаёт все точные ID через `plasticity_orient_bodies_for_print` вместе с тем же `expectedSizeMm`. MCP сверит прогноз до изменения сцены, повернёт всю группу вокруг центра объединённых B-Rep bounds одним шагом истории и измерит новые объединённые габариты Plasticity с допуском 0,01 мм. После этого оценку и нарезку нужно выполнить заново; успешная CAD-проверка не доказывает посадку в слайсер. Если ориентации недостаточно, ответ содержит `splitPlan`: полезный объём стола с учётом отступа, расчётную сетку частей, смещения плоскостей разреза, варианты соединения и требуемый зазор. После применения ориентации повторно вызовите DFM в координатах ориентированной модели. Если расчёт прочности или пользователь отметил защищённую область, передайте её как `split.protectedZones` с точным ID источника, осью и границами относительно минимального B-Rep bound. Результат предупреждает, если сбалансированный разрез пересекает такую полосу. Агент может предложить полный набор `split.cutOffsetsMm`; DFM проверит число разрезов, границы и максимальный размер каждого сегмента. Источник зоны передаёт вызывающая сторона: Workbench не проверяет, что ID относится к актуальному расчёту прочности, и отсутствие конфликта не доказывает безопасность соединения. Инструмент `plasticity_split_solid_to_build_volume` принимает одно Solid; для сборки сохраняйте взаимное расположение компонентов и разрезайте только те отдельные тела, которым это нужно. MCP получает сегментацию и координаты разрезов непосредственно из точных B-Rep bounds, создаёт и удаляет временные резаки, требует два валидных замкнутых Solid на каждый рез и проверяет суммарный объём и габариты всех частей. Для нестандартного шва доступны `plasticity_split_solid_by_plane` и `plasticity_split_solid_by_planes`. Части повторно сверяются с объёмом стола и экспортируются/нарезаются отдельно. Соединение добавляется отдельным вызовом только после выбора его типа и проверенного зазора; само отсутствие объёмного пересечения не доказывает физическую собираемость или печатный допуск. При частично выполненном разрезе агент сверяет сцену и журнал, не повторяет команду автоматически. Даже при успешной предварительной оценке задание создаётся только если G-code содержит проверяемые границы, укладывающиеся в build volume с допуском 0,01 мм.

## Восстановление

- После потери CDP или тайм-аута вызовите `plasticity_reconcile`; не повторяйте изменяющую команду автоматически.
- После неопределённой отправки на принтер вызовите `workbench_reconcile_print_submission`. Он не загружает, не удаляет и не запускает G-code.
- После конфликта ревизии перечитайте проект, покажите новые серверные значения рядом с черновиком и отправьте его снова только по явному действию.
- Аннотации к старой версии сохраняются у неё со статусом `required`; их нельзя молча переносить на новую топологию.
- Для резервной копии остановите Workbench и скопируйте каталог `.plasticity-workbench/projects`, включая `workbench.sqlite`, WAL/SHM, `.artifacts`, `.manufacturing-profiles` и приватный `owner-token`. Сохраняйте для токена права доступа только владельца.
- Ссылку или активную планшетную сессию можно отозвать в диалоге **Поделиться** на Mac. Отозванный HttpOnly-токен сразу перестаёт проходить авторизацию проекта.

SIGINT или SIGTERM закрывают WebSocket-соединения, HTTP-сервер и SQLite. Файлы моделей и артефактов не удаляются.
