# Strength operations

An inspected DCB energy preview can be preserved with plasticity_record_dcb_mode_i_energy_test only after the caller confirms that the values came from physical testing. The tool stores the selected observations and a server-recomputed MBT result in a separate content-addressed registry. Use plasticity_list_dcb_mode_i_energy_tests for compact summaries, plasticity_read_dcb_mode_i_energy_test for the full measurement record, and plasticity_match_dcb_mode_i_energy_test for exact process, interface-normal and protocol matching. These records are not traction-separation curves and are not consumed by cohesive FEA.

Plasticity MCP provides a bounded strength-first workflow for constant rectangular members, a separate flat rectangular plate body, one-fastener plate joints, the fastener member itself, heat-set-insert retention, an in-plane fastener group, exact planar critical sections and one limited solver-backed static FEA case. Codex may extract facts and ask questions, while numerical results come from deterministic formulas or the local CalculiX solver. The supported methods cover nominal axial tension, an ideal rectangular cantilever with a tip load, an elastic Euler column check, a simply supported rectangular plate under uniform pressure, one through-fastener bearing/shear-out/net-section check, one-fastener tension/shear interaction, independent insert pullout/torque retention, elastic in-plane group-load distribution, nominal axial plus biaxial-bending stress on one native planar face, and one linear-elastic C3D4 Solid with 1–8 planar support faces. Legacy support faces fully fix global translations; explicit support conditions may fix selected global x/y/z translations on each face. Uniform tractions or resultant forces/moments are applied on selected planar faces. The FEA tool reports a solver result only; it does not decide strength, safety factor or print readiness. The Euler check applies only to an ideal straight prismatic rectangular column in centred axial compression and rejects cases outside its elastic range. This is not general whole-part validation and does not cover contact, multiple bodies, rotational restraints, arbitrary boundary conditions, nonlinear material behavior, inelastic or local buckling, fatigue, impact or a structural code.

An experimental cohesive response path is available as `plasticity_analyze_cohesive_interface`. It models one printed material throughout the part and rejects records that describe another material at the interface. Its request contains one `poissonRatio` and its single matching `poissonRatioEvidence`; solver region labels A and B identify the two sides of the same material. Its Mode-I route requires a complete, hash-verified normal-tension DCB curve with interface failure; by default it uses isotropic bulk elasticity with pinned Code_Aster 15.2. When `useOrthotropicBulkProperties` is explicitly enabled, Mode-I uses Code_Aster 17.4 and applies the one exact-process coupon's homogeneous orthotropic tensor. The mixed-mode Turon route additionally requires unambiguous same-process ENF and at least two MMB records, distinct measured mode-mix fractions, traceable initial stiffness `K` in MPa/mm bound to the same exact process through `initialStiffnessEvidence.materialProcess`, and an explicit global displacement vector with both opening and shear components. The applied shear axis must match the common measured ENF/MMB direction within one degree; otherwise analysis stops before meshing because this law has one tangential response. Both routes require an unambiguous exact-process coupon and current planar support/load faces on opposite sides. Either route can apply that same measured tensor to every per-layer bulk group with its G-code-mapped frame, but only after the user confirms that exact-process coupon axis 1 represents the dominant deposited-road direction, confirms slicer-to-CAD mapping, provides complete linear or circular-arc direction evidence for every layer (up to 256), and enables `useOrthotropicBulkProperties`. Circular XY arcs with I/J center offsets or signed R radii are integrated analytically. P multi-turn arcs, malformed or mixed arc forms, non-XY planes, absolute I/J center mode and splines remain partial and cannot qualify layerwise solver orientation. This changes orientation only; it does not assign different materials or property values to layers. The input evidence is bound through the content-addressed coupon registry. The tool exports the current Solid, builds same-material bulk regions and PENTA6 cohesive interfaces, runs pinned Code_Aster, checks the CAD revision during the workflow, and saves an immutable report. Read a saved result with `plasticity_cohesive_fem_report`; that tool rechecks the CAD binding, physical interface-test/calibration records and exact-process coupon match, and marks changed or conflicting evidence stale. The report contains raw displacement/reaction/interface-state output and an indicative mesh-resolution screen. Both routes repeat the same measured, direction-independent cohesive law at each interface; neither models individual roads, within-layer raster mixtures or direction-dependent interface adhesion, and neither issues strength, safety or print-approval verdicts. Unit/MCP route tests cover both routes, and live synthetic three-layer Code_Aster 17.4 acceptances passed for both Mode-I and Turon; live MCP validation with registered physical coupon and interface records remains outstanding. A literature baseline for Creality Hyper PLA documents observed interlayer delamination and flat-coupon properties, but no direct cohesive parameters; it cannot replace exact-process DCB/ENF/MMB evidence. See [Creality Hyper PLA interlayer baseline](material-interlayer-baseline.md).

Before exporting a Solid or generating a mesh, cohesive analysis validates that the selected record contains an analysis-ready measured normal traction-separation curve and observed interface failure. A direct force-over-area specimen series alone is a nominal strength screen; it is rejected before CAD export and meshing and cannot be promoted to cohesive input.

New curve records must explicitly classify their physical fracture method as `dcb-mode-i`, `enf-mode-ii` or `mmb-mixed-mode`, consistent with normal-tension, interface-shear or mixed-mode loading and with the curve shape. The matching DCB/ENF/MMB label is required in `testMethod` too. This prevents a free-text tensile coupon or nominal peak-only record from entering a fracture route merely because its loading axis resembles a mode; classification remains caller-attested test metadata and does not verify the fixture or specimen standard.

For a directly loaded layer-normal strength screen, `plasticity_calculate_interface_specimen_strengths` calculates each nominal specimen stress as measured peak force in N divided by measured net cross-section in mm² (N/mm² = MPa). Record one force, section, observed failure location and hash-addressed source locator per physical specimen; the direct-strength interface-test record points to one representative specimen. Only samples confirmed to fail at the printed interface contribute to its minimum, maximum, mean and sample standard deviation; bulk or fixture failures remain individually visible and are excluded, and zero interface failures produce null summary values. These statistics are descriptive only. They are not a local interface traction, cohesive law, design allowable or statistically qualified bound. A failure outside the printed interface is not an interface-failure observation. This direct normal-tension screen can establish a same-process nominal Z-strength benchmark when supported by evidence, but cannot replace fracture-energy and traction-separation measurements required for cohesive analysis.

`plasticity_import_interface_fracture_csv` previews per-specimen DCB Mode-I, ENF Mode-II or MMB mixed-mode curves from explicitly mapped CSV columns. The caller must attest that the source already contains physical, compliance-corrected traction-separation values and provide units, delimiter and decimal separator. The importer converts units, validates complete curves, calculates descriptive peak/work summaries and retains the original SHA-256 and exact source record locators. It does not correct raw load-displacement data, infer a failed interface, register a test or qualify a cohesive law. Review each preview against the test method, specimen, fixture, exact print process and observed failure plane before recording it separately with `plasticity_record_material_interface_test`.

For manually selected DCB crack-growth observations, `plasticity_calculate_dcb_mode_i_energy` applies the Modified Beam Theory (MBT) crack-length correction from a least-squares fit of `C^(1/3)` against observed crack length, then returns an individual `G_I` versus crack-length curve per specimen. One calculation binds all specimens to one exact print process, test-protocol SHA-256 and date. Each selected row must contain corrected load-point displacement, force, observed crack length, locator and the source-file SHA-256. The caller must attest quasi-static linear-elastic behavior and machine-compliance correction; the tool rejects `displacement/crackLength > 0.4`, where it does not implement a large-displacement correction. It reports fit `R²`, does not filter raw machine traces or enforce a fit threshold, and leaves fixture/load-block corrections to the selected protocol. The method is exploratory for printed PLA: [ASTM D5528/D5528M-21](https://store.astm.org/d5528_d5528m-21.html) states a scope for unidirectional fiber-reinforced polymer composites, so the tool does not claim ASTM conformity. MBT is also used in the published [FDM interlayer DCB study by Lambiase et al.](https://doi.org/10.1007/s00170-023-12223-1). The result is fracture energy versus crack extension, not a traction-separation curve or cohesive strength; it is preview-only and is not registered or passed to FEA.

For a raw machine CSV, `plasticity_import_dcb_mode_i_energy_csv` provides a read-only preview. Map the exact specimen/force/displacement headers, delimiter, decimal separator, units and measurement signs; for every manually observed crack-growth point, select its CSV record number and enter the observed crack length. CSV record numbers count parsed records with the header as record 1; blank records are ignored. The importer converts force/displacement units only, checks that each selected row belongs to the declared specimen, hashes the original file and returns those exact record locators with a record-ready input and the same MBT calculation. It does not select samples, identify crack growth, filter noise, choose peaks or correct machine compliance. The caller must establish that displacement is machine-compliance-corrected and quasi-static/linear-elastic assumptions apply. Review every selected point against the physical log before separately recording a physically confirmed test; the preview never modifies the CSV or registers a test.

For a focused Mode-II initiation-energy screen, `plasticity_calculate_enf_mode_ii_energy` fits the caller-supplied initial-linear compliances `C=δ/P` against `a³`, then computes `G_IIc = 3 m P_c² a_0² / (2 b)` using the fitted slope `m`, fracture-run peak `P_c`, initial crack `a_0` and width `b`. Require at least three distinct compliance-calibration crack lengths, corrected displacement evidence, identical calibration/fracture fixture and source SHA-256 plus locator for each calibration and fracture input. It currently accepts already-reduced compliance values; it does not derive compliance from raw machine CSV, verify the fixture, determine the ASTM validity criterion or track propagation. The equation follows the ENF compliance-calibration method, but [ASTM D7905/D7905M-19](https://store.astm.org/d7905_d7905m-19.html) limits its validated scope to unidirectional carbon/glass-fiber laminates, not FDM PLA; the relation is also documented in a [published ENF study](https://journals.sagepub.com/doi/10.1177/0967391119853736). Therefore this read-only result is an exploratory printed-PLA initiation-energy estimate only. It is not an R-curve, Mode-II traction-separation curve, cohesive FEA input, strength, or design allowable. The focused planner scope `layer-interface-mode-ii` requests the measurements without requiring a full DCB/ENF/MMB cohesive calibration package.

For an exploratory mixed-mode initiation partition, `plasticity_calculate_mmb_mode_i_ii_energy` uses Reeder-Crews MMB beam theory with caller-measured critical force, geometry, exact-process flexural modulus, orthotropic E11/E22/G13 values, and confirmed material-axis mapping. The model assumes lever self-weight is measured negligible or counterbalanced and does not apply a correction. It returns separate Mode-I and Mode-II initiation energies and the Mode-II energy fraction; it does not select initiation from raw traces or replace the complete vector traction-separation curves needed for cohesive calibration. ASTM D6671/D6671M covers unidirectional fiber-reinforced composite laminates, so its validity scope does not include FDM PLA. This result is an exploratory estimate only, not cohesive input, material qualification, a design allowable, or print approval. See the [published MMB beam-theory equations](https://pmc.ncbi.nlm.nih.gov/articles/PMC8122687/).

When only raw MMB force data are available, `plasticity_import_mmb_mode_i_ii_energy_csv` previews one explicitly selected initiation record per specimen. Map specimen and force columns, units, sign, delimiter and decimal separator; supply the physically observed crack-initiation criterion, initial crack length, geometry, failure location, exact process and measured moduli. It accepts only regular non-symlink UTF-8 CSV files up to 16 MiB and 250,000 records. The importer converts force units only, preserves source SHA-256 and selected record locators, and never finds the onset or selects a peak. Review the chosen record against the test log; this preview does not register a test or create a mixed-mode traction-separation curve. After confirming the physical data, persist the same input with `plasticity_record_mmb_mode_i_ii_energy_test`; the server recomputes the estimate and stores a content-addressed immutable record. Use `plasticity_match_mmb_mode_i_ii_energy_test` only for the exact process, interface normal, shear direction and protocol hash, then `plasticity_read_mmb_mode_i_ii_energy_test` for full source evidence. This registry is independent of cohesive curves and is not used by FEA.

For raw ENF machine data, `plasticity_import_enf_mode_ii_energy_csv` provides a read-only preview from one caller-selected CSV. Explicitly map specimen/run/force/displacement columns, sign and units, then group at least three compliance-calibration runs by specimen, crack length and run ID. Manually select the initial-linear record numbers for each run and the initiation/peak record in the separate fracture run. The importer fits corrected displacement against force by least squares (with intercept), returns the compliance slope, intercept, `R²`, selected rows and original-file SHA-256, then calls the ENF `C-a³` reduction. It never detects linear regions, crack growth or peaks automatically. CSV record numbers count parsed records with the header as 1; blank records are ignored. For mixed CSV exports, review each fit, selected row range, fitted slope and intercept against the instrument log before using the preview; a high `R²` alone does not establish a physically correct compliance or valid test. The importer is limited to a regular non-symlink UTF-8 file no larger than 16 MiB and does not register test evidence.

After a reviewed ENF preview is confirmed to come from physical tests, persist the exact calculation input with `plasticity_record_enf_mode_ii_energy_test`; the server recalculates the result and creates an immutable content-addressed record. Use `plasticity_list_enf_mode_ii_energy_tests` for summaries, `plasticity_read_enf_mode_ii_energy_test` for calibration/fracture measurements and source locators, and `plasticity_match_enf_mode_ii_energy_test` only with the exact printer/material/process, global interface normal, in-plane shear direction and protocol hash. Repeated identical records are idempotent, conflicting results for the same exact query are ambiguous, and changed stored calculations fail hash/recalculation verification. This is a separate exploratory Mode-II initiation-energy registry, not a traction-separation registry or a cohesive FEA input.

`plasticity_import_interface_tensile_csv` reads a caller-selected UTF-8 CSV and previews the maximum sampled tensile force per explicitly identified coupon. The caller maps the exact specimen-ID and force headers, delimiter, decimal separator, force unit and sign, and supplies each coupon's measured net area and observed failure location. The importer hashes the original file, reports record locators and calculates only nominal peak force/area stress; it does not apply filtering or compliance correction, infer failure mode, register the test, or turn raw load traces into DCB/ENF/MMB fracture curves. Review the preview, then separately record the physical test with `plasticity_record_material_interface_test` after checking the source file and specimen observations. The production MCP transport for the tensile and processed-fracture CSV previews can be checked with `npm run accept:interface-tensile-csv -- --allow-live --output /absolute/new-directory`; it starts a separate stdio server and uses synthetic fixtures only, does not connect to Plasticity or Codex, and does not test real machine CSV data.

For measured mixed-mode interface evidence, `plasticity_record_material_interface_test` accepts a vector traction-separation curve with normal and tangential components. `plasticity_analyze_material_interface_test_curve` integrates each component's work and reports the resulting mixed-mode energy fraction. `plasticity_calibrate_turon_mixed_mode_law` fits `CZM_TURON` `ETA_BK` from immutable DCB Mode-I, ENF Mode-II and at least two MMB records with distinct measured energy fractions for the same directed single-material process and interface normal. The calibration result stores one `materialProcess` and one `interfaceNormalGlobal`, rather than describing a two-material pair. The public cohesive MCP can use those records when the user also supplies traceable initial stiffness `K` in MPa/mm, with the exact printer/material/profile/orientation/infill-percentage-and-pattern/wall-loops/top-and-bottom-shell-layers/nozzle-temperature/measured-layer-height identity inside `initialStiffnessEvidence.materialProcess`, and an explicit global displacement vector. The server rejects K evidence from another process before meshing; calibration does not infer K. The tool reports the fitted residuals and preserves the physical calibration in the saved report. This experimental route is not a qualified cohesive law; review against measurement uncertainty remains mandatory. The Turon route applies one homogeneous orthotropic tensor and print frame from the exact-process coupon to both bulk zones; it rejects different material constants or axes across the interface. Both public routes support up to 255 ordered parallel planes (a maximum of 256 modeled layers) for one same-material stack. Every interface must be included when the full stack is within this bound; taller stacks may select up to 255 planes but are explicitly incomplete and cannot support a full-stack delamination conclusion. Code_Aster `CZM_TURON` uses a single tangential strength and fracture energy for both tangent directions, so the interface response does not capture print-direction-dependent shear adhesion.

The isolated Codex analysis returns at most one next-step question package. Ask only for facts needed for the next decision and defer later-stage inputs. On every follow-up, pass each answer with its full prior question text in `answers`; this lets the stateless analysis turn adapt to uncertainty instead of repeating or listing all missing values. If the user cannot answer, ask one relevant contextual follow-up. Do not infer load, dimensions or material properties from an unscaled image.

Use a one-material model for each part; do not calculate multi-material prints. The coupon registry always requires measured E1 and its traceable evidence, while generic shear modulus and tensile/shear strengths are optional and must only be recorded when measured and relevant to the selected analysis. A solver route that needs a missing property must stop and identify that measurement; do not substitute a value or ask for unrelated properties. Orthotropic static analysis still requires its complete measured tensor and confirmed print frame. Same-material layer-interface evidence concerns cohesion between deposited layers of that one material, not bonding between dissimilar materials.

## Operating sequence

1. Call `plasticity_strength_methods` and read `plasticity://strength/workflow`.
2. Collect load, support, allowable displacement, material and manufacturing-profile evidence. Search accessible primary product and material sources before asking the user for facts already published.
   When a fastener designation is present, call `plasticity_resolve_fastener_designation` with its default combined intent and ask only `nextQuestionPackage`; its first package establishes the load path, joined materials/process, and failure consequence before final hardware or hole geometry.
   Before asking for missing coupon or layer-interface measurements, call `plasticity_plan_single_material_strength_tests` with the exact measured one-material process and only the scope required by the selected solver. It lists directional elastic/strength tests, a focused normal-tension test across layer interfaces, or same-material DCB/ENF/MMB evidence as applicable. The focused normal-tension scope records nominal peak stress only; it is not fracture energy and cannot calibrate a cohesive law. A DCB plan includes a generic-PLA literature geometry/acquisition precedent (Lambiase et al.) only as a starting reference; it is not a Creality property, normative specimen size, or sample-count requirement. Check specimen sizing against the exact material process, fixture and selected documented method, and retain explicit road/build-axis confirmation. For mixed-mode cohesive analysis, the plan routes initial stiffness `K` directly to `plasticity_analyze_cohesive_interface` with MPa/mm evidence; do not save it as an interface peak, whose registry unit is MPa.
3. When a photo or sketch has no scale, keep scale unknown. Ask only for dimensions that affect the selected method.
4. Optionally call `plasticity_analyze_strength_task`. A new request ID starts one isolated Codex app-server turn through the installed Codex API. The analysis profile has no shell, MCP, browser, CAD or print capability. Its answer is validated against a strict factual schema.
5. Call `plasticity_calculate_strength` for one labelled scenario or `plasticity_size_member` for an explicit list of candidate member heights or plate thicknesses. These tools do not read or modify Plasticity.
6. Propose one logical CAD change in the Codex chat. Execute it only under the user's accepted package or current explicit delegation.
7. Connect to the intended Plasticity window and call `plasticity_inspect_rectangular_member`. The gate reads exact native B-rep vertices, edges, faces, validity codes and revision. It never uses a render mesh or display bounds to prove dimensions.
8. Call `plasticity_verify_member_strength` with the current CAD binding and member axes. It retains the candidate evidence, adds new measured dimension records, recalculates and stores an immutable CAD-bound report.
9. Call `plasticity_strength_report` after manual CAD edits or changes to material, printer, slicer profile, orientation or process settings. Recalculate when it reports `stale`.
10. For bounded static FEA, call `plasticity_match_material_coupon_data` first when a measured material coupon may match the active process. New physical coupon records must include the measured slicer layer height; an exact match includes printer, material, profile hash, orientation, infill percentage and pattern, wall loops, top/bottom shell layers, nozzle temperature and layer height. Legacy records without these process settings remain readable but cannot qualify for a new exact match. Only an unambiguous exact match can bind Young's modulus to FEA; pass the selected record ID/process and its exact modulus, which the MCP verifies against the immutable registry. If compatible partial records are ambiguous because no single record contains all their measurements, ask the user to confirm the unique specimen count and consolidate them with `plasticity_combine_material_coupon_data`; conflicts still require the user to resolve which physical measurement applies. For an orthotropic print model, do not treat a uniaxial coupon as a full tensor: provide `orthotropicMaterial` with E2/E3, nu13/nu23, G12/G13/G23, separate exact-value evidence for each, and user-confirmed or sourced global print axes; the legacy top-level Young’s modulus and Poisson ratio are E1 and nu12. Ask about unknown print axes instead of inferring them from a photo or CAD face. Orthotropic mode rejects von Mises allowables and uniaxial-only coupon bindings. It can optionally accept nine directly traceable, already factored X/Y/Z tensile and compressive and XY/XZ/YZ shear limits in `orthotropicMaterial.factoredAllowables`, each with exact evidence and an applicability/design-factor basis; the resulting local componentwise maximum-stress screen does not include multiaxial interaction and is diagnostic only. It assumes a homogeneous orthotropic continuum and does not model layer interfaces, delamination or joints between different materials; matched interlayer tests may inform Z-tension and XZ/YZ-shear values but do not make this a cohesive-interface analysis. Never substitute generic strength or a raw coupon peak for those limits. Without a coupon binding, supply `youngsModulusEvidence` exactly equal to `youngsModulusMPa`; measured/sourced values need a URL, SHA-256 and locator. `poissonRatioEvidence` is always required and must exactly equal `poissonRatio`. A physical coupon record may include measured nu12 and a complete orthotropic tensor. For static orthotropic FEA, bind it with `orthotropicMaterial.couponRecordId` and `process`, and reference the same ID through `materialCoupon`; the MCP checks E1, nu12, all seven remaining constants, each evidence object and the confirmed print frame against the exact-process immutable record, then rechecks the binding when the report is read. Without that binding, supply exact traceable evidence for every property. Assumed properties require a reason and remain scenario-only. Then call `plasticity_analyze_static_fem` only after the user or a traceable source establishes each of 1–8 support faces and which global translations are fixed (legacy `supportFaceIds` means x/y/z fixed), explicit face tractions and/or resultant forces with application points and free moments, isotropic material constants and mesh size. A partial restraint can leave rigid-body modes or make the solver singular; it is not contact, friction or a rotational support. Use named `loadCases` when evaluating distinct physical scenarios; the old top-level load arrays remain a one-case shorthand. Set `meshRefinementSteps` to 1–3 for two to four successively halved mesh levels when a numerical trend is needed. The report labels only the sampled direction for raw maximum von Mises and observed displacement; this is not a convergence or strength verdict. For longer studies, run analyses with identical CAD and physical inputs at successively finer base sizes, then call `plasticity_compare_static_fem_refinement_reports` with their report IDs. It verifies the common CAD binding, exact input and native geometry evidence, and byte-identical repeated mesh hashes with reproduced solver outputs before it combines levels. The solver job count per analysis is capped at 12. Each named case is solved separately. The tool exports one current Solid, maps exact planar face IDs into STEP, generates C3D4, transfers each uniform traction or face force/moment as nodal loads, runs CalculiX, sums reactions across all support faces and persists each solver summary. Every calculation reports the maximum raw C3D4 integration-point stress element and that tetrahedron's centroid in millimetres, bound to the reported mesh and CAD revision. This point does not define an averaged stress field or a finite critical-region boundary; it cannot by itself protect a split seam or authorize reinforcement. Selected faces that share mesh nodes are rejected. Read `plasticity_static_fem_report` to check freshness; a referenced coupon report becoming missing or ambiguous also marks the FEA stale. The comparison tool reports freshness separately. Isotropic reports with a factored von Mises allowable return its diagnostic raw-peak comparison. Orthotropic reports with all nine factored directional limits return a local componentwise maximum-stress screen; it omits multiaxial interaction. That screen assumes one homogeneous material and does not check layer interfaces, delamination or different-material joints. These screens never return a strength pass/fail result.

For layerwise static analysis, first obtain the exact process hash, measured layer height, a complete slicer layer-road direction schedule, and a user-confirmed slicer-to-CAD mapping. Confirm that the exact-process coupon axis 1 represents the dominant deposited-road direction. Call `plasticity_plan_cohesive_layer_planes` for the placed Solid and copy its profile-bound `plan` into `layerPlanePlan` for `plasticity_analyze_static_fem`; the static analysis derives conformal layer regions from the ordered planes and assigns the same measured orthotropic tensor to each region using that layer's confirmed frame. The interface is assumed perfectly bonded. This solver path does not model multiple materials, per-layer property changes, individual roads, raster mixtures, delamination or direction-dependent interface adhesion, and it does not make a strength/print-readiness decision. Fixed-frame directional allowables are rejected in this mode; the optional nine-value directional screen applies only to the homogeneous fixed-frame analysis.

Model one material and one print process per analyzed part. The optional orthotropic Tsai-Wu first-failure screen requires nine measured un-factored directional strengths and three normalized interaction coefficients derived from biaxial tests. Store them in `orthotropicMaterial.tsaiWuCriterion` inside an immutable `plasticity_record_material_coupon_data` record: each value points to one exact evidence entry, each derived interaction points to a measured biaxial test entry, and the record content hash includes printer, material, profile, orientation, infill percentage and pattern, wall loops, top/bottom shell layers, nozzle temperature and layer height. Use `plasticity_match_material_coupon_data` to retrieve only an exact process match, then pass the selected ID as `orthotropicMaterial.tsaiWuQualificationRecordId` with the same `orthotropicMaterial.process`; the server loads values and evidence and checks print axes. Conflicting strength/interactions return `ambiguous`. Missing physical data stays missing; the screen reports integration-point failure index and proportional load factor only, never a strength verdict or safety factor.
For physical layer-adhesion evidence, use `plasticity_record_material_interface_test` with one exact material/process identity shared by both sides, the global interface normal and load direction, test mode, test-protocol hash, measured result and observed failure location (`interface`, `printed-material`, `mixed`, `fixture` or `unknown`). `plasticity_match_material_interface_test` matches that single process, test direction and protocol. The public MCP accepts one material only; records for other interface types are not exposed to this workflow. These records preserve experimental observations only; they are not design allowables and are not consumed by the current homogeneous CalculiX analysis.

Before solver execution, the MCP also checks from actual support mesh nodes that fixed translations constrain all six global rigid-body translation/rotation modes. A deficient rank stops the analysis. Rank six does not confirm the real support model or rule out local mechanisms, instability or failure.

For a mixed bracket or enclosure, identify the plane that represents the critical load path. When it coincides with an existing planar face, call `plasticity_inspect_planar_section` with the current body, face, revision and an in-plane X direction. When the section lies inside the Solid, call `plasticity_inspect_arbitrary_section` with an origin, normal and in-plane X direction. It cuts a native clone in a temporary database and proves that the persistent geometry and history stayed unchanged. Both paths read exact native line and circle boundaries; neither uses display bounds or a render mesh as measurement evidence. Use `plasticity_calculate_section_strength` for an unbound scenario. To bind either type of section report, pass the corresponding face or plane binding to `plasticity_verify_section_strength`; it re-reads the exact section, replaces the loops, frame and properties with native measurements, recalculates, checks the binding again and stores the immutable report. Later report reads re-inspect arbitrary planes and detect changed plane, topology, revision, body, document or session.

For a rectangular tongue root, call `plasticity_inspect_tongue_root_section` with a plane normal to the tongue's lever arm, X aligned to root width and Y aligned to bending thickness. It accepts only one exact four-edge straight-line rectangle without holes and reports the native measured dimensions. Pass that result's plane binding to `plasticity_verify_tongue_root_strength`; it re-reads the section, replaces both dimensions with exact B-rep evidence, calculates the limited beam screen, confirms the binding again before storing, and checks the same topology on later report reads. Force, lever arm, material properties and the shear correction factor remain scenario evidence. The report also stores the printer ID, immutable printer/process/filament profile hash, orientation, infill, temperature and effective-section qualification; a profile or orientation change makes it stale. This method cannot pass the complete joint.

If several planes are plausible, use `plasticity_inspect_arbitrary_sections` to inspect up to 32 explicit candidate frames, or `plasticity_scan_arbitrary_sections` to generate 2–32 evenly spaced stations along a caller-selected section normal and offset range. Both inspect sequentially against one body and revision, return exact geometry evidence, and fail the whole request if the session, document, body or revision changes. They do not infer the load path, calculate or rank strength, or claim the strongest section; the agent must choose the axis and submit a selected verified plane to the strength workflow.

When one load/material scenario should be compared across those stations, use `plasticity_scan_section_strength`. The tool replaces caller geometry with each exact native section, runs the existing deterministic nominal-section calculation, sorts supported results by their largest single-mode utilization, and saves one immutable report containing each measured input, calculation, unsupported-station reason and the aggregate ranking. It does not combine stress modes or include local concentration, support compliance, joints or whole-part failure. Any unsupported station or station without a numeric utilization makes the overall ranking incomplete and suppresses a global governing-station claim. Read the report with `plasticity_section_strength_scan_report`; it checks the stored session/document/revision/body against the live CAD binding and reports `current`, `stale` or `unverified`. The compact scan response omits section loops; re-inspect the selected plane to obtain loops/frame, then call `plasticity_verify_section_strength` to save a CAD-bound single-section report.

Workbench is optional throughout this sequence. The user may inspect the part directly in Plasticity and continue the conversation in Codex.

For a separate flat rectangular lid or panel, `simply-supported-plate-uniform-pressure-v1` uses exact prism dimensions as its two spans and thickness. An integral plain rectangular enclosure wall can now supply those dimensions through `plasticity_inspect_integral_rectangular_plate` and `plasticity_verify_integral_plate_strength`, which read exact opposed planar face B-reps on one Solid and replace caller dimensions. The inspector accepts equal outlines or an inner outline inset by one measured wall thickness on each span. Before choosing the method, establish the net uniform pressure and the real condition of all four edges. The method is valid only for explicitly confirmed ideal simple supports, constant thickness and homogeneous-isotropic-equivalent response. A clipped or screwed cover, ribbed panel, opening, boss or curved surface is not automatically covered by this model.

For a plate carrying one pin, bolt or screw in in-plane shear, select the two
opposed broad faces and give the in-plane load direction to
`plasticity_inspect_single_fastener_plate`. The exact gate accepts only a plain
rectangular Solid with one circular through-hole. It measures the loaded and
opposite centre-to-edge distances, transverse width, thickness, diameter and
side clearances. Use `plasticity_calculate_single_fastener_strength` for an
unbound scenario and `plasticity_verify_single_fastener_strength` for a current
CAD-bound report. Supply distinct traceable bearing, shear and tensile limits
for the actual material, printer profile and orientation.

Check the physical bolt, screw or pin separately with
`plasticity_calculate_fastener_member_strength`. Supply sourced or measured
tensile stress area and effective area for each actual shear plane rather than
deriving both from nominal diameter. State whether one or two equal shear
planes carry load and whether they cross the smooth shank or threads. The
axial load must include applicable preload. The tool reports direct tension and
shear plus the NASA screening relation `R_t² + R_s³ ≤ 1`; combined loading also
requires explicit confirmation that this interaction criterion is appropriate
for the task.

For a heat-set insert, use `plasticity_calculate_heat_set_insert_retention`
with the worst-case loads already resolved to one insert. Pullout and torque-out
capacities must be measured or sourced and tied to the exact insert ID, host
material, printer/profile, orientation, hole, and installation process. The
method checks both modes independently. Simultaneous nonzero pullout and torque
stay conditional because the passport does not invent an interaction equation.

For two or more fasteners, use `plasticity_distribute_fastener_group_load`
after recording every transfer-point coordinate, the two in-plane force
components, the point of application and any free moment in one frame. The
method combines an equal direct-force share with the elastic moment share about
the group centroid. Loads are not factored by the tool. Optionally provide one
traceable configuration-matched design allowable in N for every fastener via
`shearCapacities`; each value must already include the required safety factor.
The resulting individual shear comparison is conditional unless the load model
is fully confirmed, and it never checks the joined plates or full joint. Without
these allowables, the result remains load distribution only; send each demand
to the applicable plate, insert or other fastener method.

On a rectangular mounting face, `plasticity_check_fastener_group_layout` can
take an explicit `opposedFaceId` to verify matching exact hole profiles on both
sides and measure native B-rep plate thickness. This is geometry evidence only;
it does not establish a load path or capacity.

The single-fastener plate passport assumes one hole; do not repeat it for each
hole in a group and aggregate those outputs. For a supported rectangular
multi-hole plate, `plasticity_verify_fastener_group_plate_bearing` binds one
elastic in-plane group demand to exact opposed faces, cylindrical hole faces,
and measured thickness. It screens per-hole projected bearing and can add a
separate straight-cut net-tension check with an explicit external plate
resultant, or aligned per-hole two-plane edge shear-out. Each mode needs its
own traceable allowable matched to the exact material/process and already
including the safety factor. The straight-cut net-tension model considers all
parallel cuts normal to local X or Y and subtracts the exact circular-hole
chords. Diagonal load directions for edge shear-out and `e/d < 1.5` are
unsupported; `1.5 ≤ e/d < 2` is conditional. These are bounded local screens,
not an overall pass. Angled/staggered paths, compression buckling,
shared-ligament interaction, bypass, plate bending, prying and full-joint
strength remain unchecked. NASA's group-loading guidance explicitly notes
that clearance and hole-position tolerances can prevent equal load sharing;
its metal guidance does not qualify printed-polymer properties. Never derive a
plastic allowable from nominal M size or a generic filament label.

## Evidence and outcomes

Every required numeric input is assigned to an evidence record. Records distinguish measured, sourced, derived, assumed and unknown values and carry units, dependencies and source locators. Mass becomes force only through an explicit gravity record. A model answer cannot add calculation fields or CAD commands to the analysis result.

Strength outcomes are `needs-input`, `unsupported`, `conditional`, `pass` or `fail`. The group distribution uses `calculated` instead of `pass` because it has no capacities. Unknown material properties, unmatched printer/profile/orientation data, or unconfirmed method assumptions keep a result conditional or incomplete. Exact CAD geometry does not upgrade physical evidence. All reports list unchecked scopes.

`plasticity_calculate_strength`, `plasticity_calculate_section_strength`, `plasticity_calculate_single_fastener_strength`, `plasticity_calculate_fastener_member_strength`, `plasticity_calculate_tongue_root_strength`, `plasticity_calculate_threaded_receiver_strength`, `plasticity_calculate_heat_set_insert_retention` and `plasticity_distribute_fastener_group_load` always label their output as scenarios. Native verification tools may bind supported measured geometry. Section, single-fastener-plate and group-plate-bearing reports become stale when their selected faces or native topology signature change. Fastener-member, threaded-receiver, insert-retention and group-distribution reports have no CAD binding and become stale when their load, geometry, qualification, process, evidence or safety factor changes. A bound tongue-root report becomes stale when its root-section plane, native topology or any scenario input changes.

The plate method evaluates the Navier double series for centre deflection and centre bending stresses under static uniform pressure. It requires a sourced or measured Poisson ratio, a short-span/thickness ratio of at least 10 and centre deflection no greater than half the thickness. Other support conditions and general shell geometry remain unsupported.

The `euler-column-buckling-v1` method checks a straight rectangular column under centred axial compression. It uses the weaker section axis and requires traceable evidence for Young's modulus, elastic limit, compressive allowable and effective-length factor. It reports elastic Euler buckling and nominal crushing utilizations separately. If the predicted Euler stress exceeds the supplied elastic limit, the result is `unsupported` and explicitly does not claim the member is safe; inelastic, eccentric, imperfect, local and torsional buckling remain outside the method. Live stdio MCP acceptance on Plasticity 26.1.3 measured a native 200 × 20 × 10 mm Solid, persisted a current CAD-bound Euler report, detected the report as stale after a native geometry edit, and restored the empty test scene. Synthetic material data stayed conditional. This verifies software/native-geometry integration, not physical column strength.

The planar method supports exact line and circular boundaries. It calculates nominal normal stress from axial force and biaxial bending. Direct shear is supported only for a proven solid rectangle, solid circle or concentric circular annulus with a sourced or measured shear limit. Elastic torsional shear also supports one centered, uniform-thickness rectangular single-cell wall under the explicitly confirmed Bredt-Batho thin-wall idealization. Results name the selected direct-shear and torsion formula families. An inner boundary keeps local stress concentration and net-section fracture conditional. Other section families, torsional twist and combined transverse shear plus torsion are unsupported. Unsupported resultants remain visible beside any partial nominal stress values.

The multi-hole group-plate tool uses each fastener's elastic resultant and exact native hole diameters and opposed-face thickness for local projected bearing, compared with a directly traceable, already factored allowable for the exact print/material configuration. It can optionally add `netTension` when the user supplies the external plate tensile resultant, chooses local X or Y, provides a separate factored tensile allowable and confirms uniform membrane tension, centered through-thickness loading and a straight transverse failure path. The solver searches all parallel straight cuts normal to that axis and subtracts the exact circular-hole chord widths to find the minimum net width; stress is `demandN / (minimumNetWidthMm * thicknessMm)`. It can also add `edgeShearOut` for aligned per-fastener resultants using the single-hole nominal formula `F / (2·t·(e − d/2))`, exact distance from each hole center to its loaded rectangle edge and a separate factored shear allowable. A physical-test benchmark additionally requires a selected immutable record, the exact recorded print process, an evidence-backed dimensional tolerance, and caller confirmation that both the part process and fixture/load path match. Plate dimensions and a one-to-one hole-coordinate/diameter mapping are checked against current B-rep geometry within that tolerance; the report exposes signed specimen-minus-CAD plate deltas and maximum hole-center and hole-diameter deviations. Ambiguous registry outcomes or geometry mismatch are rejected. The report compares the factored external tensile demand with the lowest observed specimen peak load. It remains a conditional benchmark only: it is not a statistical design allowable, does not establish strength pass/fail, and does not prove unobserved failure modes. Only local X/Y aligned vectors are supported; diagonal vectors and e/d below 1.5 are unsupported. Ratios between 1.5 and 2 remain conditional. These checks are nominal local screens, not overall passes. Net tension does not infer external plate tension from per-fastener demands. Angled/staggered fracture paths, compression-side buckling, shared-ligament interaction, unsupported tear-out directions, bearing-bypass, plate bending, prying and complete-joint strength remain unchecked. Live acceptance uses synthetic allowables only, not material values or design recommendations.

The single-fastener method reports three separate stresses and utilizations. It
requires `e/d ≥ 1.5`; the interval below the nominal `2d` edge practice stays
conditional. It does not check the fastener itself, preload, slip, clearance,
prying, pull-through, inserts, threads, fatigue or interaction in a fastener
group. Those remain visible in every report.

The tongue-root method checks a rectangular prismatic root under a single
transverse point load using bending stress, maximum rectangular-section shear,
and bending plus Timoshenko shear deflection. It requires traceable geometry,
load, orientation-matched effective material properties and shear correction
factor, and captures printer/profile hash, orientation, infill, temperature
and effective-section qualification. Any root-level non-exceedance remains
`conditional`; groove contact, wall splitting, stress concentration,
mating-part strength and whole-joint safety are never covered by that result.

The fastener-member method uses the explicitly supplied tensile stress area and
the effective shear area multiplied by one or two confirmed shear planes. Its
factored ratios are `R_t = F_t SF/(A_t S_t)` and
`R_s = F_s SF/(n A_s S_s)`. When both loads are nonzero, the screening result
also requires `R_t² + R_s³ ≤ 1`. It rejects effective areas larger than the
nominal circular shank area and never chooses a thread table or material grade
from nominal diameter alone. Bolt bending, slip and clamp loss, load
redistribution, thread or insert pull-out, joined-member failure, fatigue and
critical-use qualification remain unchecked.

The threaded-receiver method applies the safety factor once to the worst-case
axial demand and compares it with three explicit compatible allowable loads:
internal-thread stripping, external-thread stripping, and fastener tension. It
also checks the requested failure hierarchy from the allowable loads. Pitch,
engagement, and fully formed thread count identify the qualified configuration;
they do not generate an implicit capacity. A procured nut or threaded insert
using only a nominal shear-area calculation is unsupported. Parent-part
pullout, boss splitting, transverse shear, prying, preload generation, fatigue,
temperature, and group distribution remain unchecked.

The heat-set-insert method applies the safety factor independently to per-insert
axial demand and per-insert torque demand. It compares those values with the
matched pullout and torque-out qualification. It also reports the manufacturer
hole-depth guidance `insert length + 2 × thread pitch`; falling below it keeps
the result conditional. A capacity mismatch is unsupported, while data whose
match to the print and installation process is not established stays
conditional. The method does not distribute a group load among inserts and
does not check combined-mode interaction, transverse shear, boss splitting,
threads, the screw, fatigue or installation defects.

## Isolation and persistence

The launcher uses the installed Codex executable only to start its App Server JSON-RPC API over stdio, and verifies the supported executable version and protocol hash before enabling analysis. It does not call the public OpenAI API. Each new request owns one ephemeral thread and one turn. Local image inputs must be regular PNG, JPEG, HEIC, or HEIF files under `PLASTICITY_STRENGTH_ASSET_ROOT`, the signed-in Codex user's `~/.codex/attachments`, or an explicitly configured root in `PLASTICITY_STRENGTH_IMAGE_ROOTS` (platform path separator). Resolved symlink targets must remain inside an allowed root. On macOS, HEIC/HEIF is converted locally to JPEG by `/usr/bin/sips`; the original bytes are fingerprinted and checked before conversion. On other platforms, convert HEIC/HEIF to PNG or JPEG before analysis. At most four original and converted images of 20 MiB each are accepted. The whole turn has one deadline. Cancellation interrupts an active conversion or Codex turn and closes its process.

Reports and request states are private JSON files below `.plasticity-mcp/strength` by default. Set `PLASTICITY_STRENGTH_ROOT` to a trusted process-level directory. Public tools accept record IDs and never paths into this store. Existing reports are never overwritten.

An interrupted, failed or timed-out request is terminal and is never retried automatically. Read it with `plasticity_strength_request` and use a new request ID for a deliberate new attempt. If Plasticity changes during inspection, the geometry evidence is discarded. Reconnect or read the new revision, then inspect again.

The tools stop at analysis and CAD verification. They do not approve or start a print.
